## 根据位置决定处理方式

按流程表格，本仓库属于「**已本地提交，未推送**」→ 保留工作备份，在受控副本中改写相关提交；检查全部拟发布历史。

| 步骤 | 实际做法 |
|---|---|
| 保存完整备份 | `git bundle create --all` 全量备份到工作区内的受控目录，`git bundle verify` 通过 |
| 受控副本中改写 | `robocopy /E /XD node_modules` 建副本 → 副本内 `git filter-branch --tree-filter` 跑脱敏脚本 → 删 `refs/original` → `reflog expire` + `gc --prune=now` |
| 改写范围 | 历史版本中 `AGENTS.md`、`docs/DESIGN.md`、`.verify/diagnose-desktop-compose.mjs`、`.verify/gui/drive.mjs`、`.verify/REPORT.md` 里的本机路径 → 占位符（`<repo>` / `<npm-global>` / `<app-dir>` / `<chrome>`）；提交说明里没有路径，未改 |
| 回收 | 用 `git fetch` 把副本的 `main` 取回原仓库，确认与当前 `main` 无内容差异后 `reset --hard`；再 `reflog expire` + `gc --prune=now` |
| 隔离旧历史 | 旧提交已从本地对象库清除（`Not a valid object name`），只保留在受控备份 bundle 中 |

## 验证记录

核验日期：2026-10-07（北京时间 15:55，16:06 追加 git 层复核）。核验方式：**GitHub REST API + 未登录网页**，随后在**一次性更宽权限**下用 `git ls-remote` / `git fetch` 复核（受限令牌下 schannel 取不到 TLS 凭据，会报 `SEC_E_NO_CREDENTIALS`）。「有权限访问」一列仍为不适用 —— 本会话未用任何 GitHub 凭据做认证访问。

| 位置/范围 | 有权限访问结果 | 未登录访问结果 | 结论与待办 |
|---|---|---|---|
| 新仓库与默认分支 | 不适用 | **public**；默认分支 `main`；远端 HEAD = 本地 HEAD `f287e74`；远端 8 个提交，全部为改写后的编号 | 远端历史 = 改写后历史，与本地一致 |
| 已替换的旧隐私提交 | 不适用 | **API 422**「No commit found for SHA」+ **未登录网页 404** | 改写前的旧 HEAD 在 GitHub 上不可读 ⇒ 旧历史从未推送 |
| 旧标签/附件 | 不适用 | 远端 `tags` 为空；无 Releases | 无旧标签需要处理 |
| 活动记录、PR 和其他引用 | 不适用 | 远端只有 `main` 一个分支；Issue / PR / Star / Fork 均为 0 | 无引用残留 |
| Fork、克隆、外部缓存 | 不适用 | Fork 数 0 | 已扫描工作区，未发现本仓库的其他克隆或副本 |

> 说明：`404` 只表示该请求当前拿不到目标资源（私有仓库未登录同样返回 404），因此上表的「不可读」结论是针对**已确认公开**的这个仓库得出的；`422` 则明确表示该 SHA 不存在。
